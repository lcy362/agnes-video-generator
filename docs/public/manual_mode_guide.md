# 手动模式使用指南（v6.0）

> 手动模式允许你在视频生成的**检查点**暂停，确认或修改产物后再继续，可配合本地 AI Agent 精细化控制生成效果。
> 方案细节见 `docs/plans/v6.0/manual_mode_PRD.md`。

---

## 一、什么是手动模式

默认「自动模式」一次跑完整个流水线；「手动模式」会在你选择的检查点暂停，等待你处理产物。

```
scenes(分镜) → references(参考图) → videos(视频片段) → audio(配音) → subtitle(字幕) → final(成片)
                      ↑ 在任一暂停点停下来，处理产物后点「确认并继续」
```

- 创建任务时选择「✋ 手动」并勾选要暂停的检查点（默认按任务类型预填）；
- **运行中可随时切换**：任务卡片上的「切为手动 / 切回自动」；
  - 自动 → 手动：任务在下一个安全点挂起，进入检查点等待页；
  - 手动 → 自动（切换即继续）：清空暂停点并立即跑完；
- simple / 简单图片 类型不支持手动模式（仅完成后展示产物清单）。

## 二、三种产物处理方式（任选其一）

| 方式 | 适合场景 | 操作 |
|------|---------|------|
| 🤖 **AI 帮我改** | 快速改文案 / 分镜 / 字幕 | 输入修改要求 → 系统调模型修改 → 查看 diff/对比 → 应用 |
| ✏️ **我自己改** | 想要完全控制 | 复制产物路径 → 本地编辑 → 点「已修改，继续」 |
| 🤝 **外部 Agent** | 复杂处理（ffmpeg / PIL / 批量） | 复制命令 + 提示词 → 本地 Agent 处理 → 点「已修改，继续」 |

三种方式最终都会触发「修改前提示」：系统列出将删除重跑的产物与保留的产物，确认后按**产物级依赖图**重跑——只重跑受影响的，不影响的不动。

例如：
- 改**旁白文本** → 只重跑配音 / 字幕 / 成片（参考图、视频保留）
- 改**画面描述** → 重跑参考图 / 视频 / 成片（配音、字幕保留）
- 改**场景视频** → 重跑配音 / 字幕 / 成片（其他场景视频保留）

## 三、外部 Agent 协作 Prompt 库

> 以下示例面向支持"读取本地文件 + 执行命令"的本地免费 Agent（TraeWork / opencode / workbuddy / CodeBuddy CLI）。
> `<任务目录>` 在 Web 端已自动填充为真实路径，复制即用。

### 示例 1：优化分镜（scenes 检查点）

```
你是资深视频分镜导演。请读取文件 <任务目录>/script.json，对其中每个场景的视频生成描述进行优化：
1. 保持 JSON 结构、场景数量、每个场景的 narration_text（旁白）与 duration 完全不变；
2. 仅增强 scene_prompt / end_frame_prompt 的画面描述，要求：
   - 明确主体、构图、镜头运动（推/拉/摇/移）、光线氛围、色彩基调；
   - 与前后场景的视觉连续性保持一致（统一角色外貌、色调）；
   - 每条不超过 80 个中文字符；
3. 语言与原文一致（中文）；禁止添加 JSON 之外的任何字段；
4. 输出：先给出改动摘要（每条一句话），再输出完整的、可直接覆盖原文件的 JSON 内容。
完成后请将结果写回 <任务目录>/script.json（UTF-8、缩进 2 空格）。
之后用户会在网页上点击"已修改，继续"，系统会基于新分镜重新生成参考图与视频。
```

### 示例 2：润色旁白（audio 检查点前）

```
请读取文件 <任务目录>/combined_narration.txt（或 script.json 中所有 narration_text 拼接），
将这段视频旁白润色为更适合朗读的口播稿：
1. 保持原意与信息量不变，总字数变化不超过 10%；
2. 句子改为短句、口语化，去掉书面连接词与被动语态；
3. 按 4 字/秒估算，控制总时长约 <总时长> 秒；
4. 分段以空行分隔，段数与顺序保持不变（每段对应一个视频场景）；
5. 只输出润色后的纯文本，不要任何解释。
请将结果写回 <任务目录>/combined_narration.txt。用户在网页点击"已修改，继续"后，
系统会重新生成配音与字幕。
```

### 示例 3：修正字幕（subtitle 检查点）

```
请检查并修复字幕文件 <任务目录>/full_subtitle.srt：
1. 用 ffprobe -v error -show_entries format=duration -of csv=p=0 <任务目录>/combined_narration.mp3
   获取音频实际时长，确保最后一条字幕的结束时间不超出音频时长；
2. 相邻字幕不得重叠（允许 50ms 间隔）；每条字幕时长 ≥ 0.3 秒；
3. 中文单条不超过 18 个字符，或拆分两行；英文按单词断句，每条 ≤ 2 行；
4. 保持序号连续、时间格式 HH:MM:SS,mmm；
5. 输出修改前后对比摘要，并将修复后的完整 SRT 写回 <任务目录>/full_subtitle.srt。
```

### 示例 4：处理视频片段（videos 检查点）

```
请用 ffmpeg 处理 <任务目录>/scene_2/video.mp4：
1. 抽帧检查：输出第 1、2、3 秒的关键帧到 <任务目录>/scene_2/frames/ 目录（PNG）；
2. 若画面质量可接受，无需改动，直接输出"无需处理"；
3. 若需处理（如裁剪、调色），用 ffmpeg 输出到 <任务目录>/scene_2/video_fixed.mp4，并打印所用命令；
4. 不要重新编码音频，保持原有画面比例。
```

### 示例 5：处理参考图（references 检查点）

```
请用 Python PIL 处理 <任务目录>/character_reference.png：
1. 将主体人物居中，背景虚化（高斯模糊）；
2. 统一输出 768x1152，质量 95 的 PNG；
3. 保存为 <任务目录>/character_reference_v2.png，并打印图片尺寸。
```

### 逐段补图（v8.1）

稿件长视频创建时勾选「生成前暂停，等我补图」，任务会在 `references` 检查点停下。
此时检查点页顶部会出现**逐段补图**面板：

- 每段一行，显示该段文本片段、已上传张数与剩余额度；
- 可给任意段上传 1~N 张内容图（顺序即提示词里的 `<Picture 1>`、`<Picture 2>`）；
- 剩余额度 = 模型上限 −（人物板 + 风格板 + 衔接静帧 1 张）；
- 保存后**覆盖**该段原有内容图，点「继续」恢复生成。

接口等价形式：`POST /api/tasks/{task_id}/scene-refs`（表单 `scene_index` + `reference_images`），
只在任务处于暂停等补图状态时可用（否则 409）。

## 四、协作协议（外部 Agent 需遵守）

| 项 | 约定 |
|----|------|
| 文本编码 | UTF-8 无 BOM |
| JSON | 缩进 2 空格，`ensure_ascii=False`，只改指定字段 |
| SRT | 标准 SubRip，序号连续 |
| 图片 | PNG（覆盖上传兼容 jpg/png/webp） |
| 视频 | MP4（H.264 + AAC） |
| 回填方式 | 覆盖原文件名 或 上传新文件 |
| 副作用 | 回填后下游步骤按依赖图重跑 |

## 五、外部素材模式（v7.6，即梦协作）

> ⚠️ **试验功能**：外部素材模式（即梦协作）自 v7.6 起提供，仍在打磨——检查点提示词、
> 批量导入与字幕对齐都可能继续调整。界面上该功能的入口（执行模式「🌐 外部素材」、
> 「视频生成工具」下拉、检查点的「🎬 即梦协作」卡片）都带「🧪 试验中」气泡，
> 旁边给出**官网说明**与**常见问题**链接（按界面语言跳对应语言版本）：
>
> - 📖 使用说明：<https://video.lichuanyang.top/guides/jimeng-workflow>
> - ❓ 常见问题（含 Agnes 503 / `video queue is full` 处理办法）：<https://video.lichuanyang.top/faq/jimeng>
>
> 遇到问题请附任务 ID 反馈，欢迎把你用这套流程做出的作品发给我们。

> 外部素材模式是**手动模式的增强版**：同样在检查点暂停，但在每个检查点额外给出
> **面向外部视频生成工具**的协作提示词——你用即梦（Dreamina）等工具生成分镜视频/图片，
> 再批量导回本项目，由本项目完成归一化、拼接与字幕对齐。方案见
> `docs/plans/v7.6/external_asset_mode_PRD.md`。

### 5.1 与手动模式的区别

| 项 | 手动模式 | 外部素材模式 |
|----|---------|-------------|
| 执行模式 | `✋ 手动` | `🌐 外部素材` |
| 检查点提示词 | 面向「本地 AI Agent 改产物」 | 面向「即梦等工具的**生成指令**」（含画面 + 音频 + 时长约束） |
| 音频来源 | 本项目 TTS（edge_tts） | 可选：**使用视频自带音频**（保即梦原音轨）/ 使用本项目配音 |
| 字幕来源 | 本项目旁白 | 可选：**旁白** / **人物对白**（仅外部素材模式；对白由编剧逐场景生成，字幕取自对白） |
| 素材回填 | 上传单文件 / 本地编辑 | **批量导入**（多选 mp4/png，自动归一化 + 探针回显） |

### 5.2 使用步骤（以即梦为例）

1. 创建任务时选「🌐 外部素材」，选择「视频生成工具」（首期仅 **即梦**）；
2. 选「音频来源」：
   - **使用视频自带音频（推荐）**：保留即梦生成视频里的音轨，本项目**不再生成 TTS**
     （不会产出 `combined_narration.mp3`，字幕按各分镜真实时长对齐）；
   - 使用本项目配音：与普通手动模式一致，用 edge_tts 生成旁白并叠加（会替换原音轨）。
3. 选「字幕来源」（仅外部素材模式）：
   - **旁白（默认）**：字幕文本用剧本旁白；
   - 人物对白：编剧逐场景生成对白（落 `scenes[].dialogue`），`videos` 提示词附「台词（对白）」，
     字幕文本取自各场景对白。
4. 任务在各个检查点暂停。每个检查点新增一张「🎬 即梦协作」卡片：
   - 一键复制**协作提示词**（已自动填好任务目录、场景数、总时长）；
   - 按**回填指引**把产物导回（详见 5.3）。
5. 在 `videos` 检查点用「批量导入」选中即梦导出的多个 mp4 → 系统自动
   **归一化到任务分辨率/帧率/编码**，并回显每条素材的时长/分辨率/帧率/是否有音轨。
   > `videos` 检查点**确认（approve）前会校验素材已导入**：缺失场景视频 → 422。
   > 视频是否含音轨**不做拦截**，由用户自行负责（导入回显中会标黄提醒）。

> **音频约束**：选「使用视频自带音频」时，`audio` 检查点**自动通过**（不暂停）；
> 字幕时间轴按各分镜视频的**真实时长**估时，与拼接后成片对齐。
> 提示词中会要求即梦「生成同步音频」，并要求台词文本与 `script.json` 的
> `narration_text` 逐字一致——本项目据此生成字幕，因此**台词内容与顺序务必保持一致**。

### 5.3 批量导入与探针

| 操作 | 说明 |
|------|------|
| 端口 | `POST /api/tasks/{id}/artifacts/import`（multipart `files[]` + `kind=image\|video`） |
| 命名映射 | 文件名含序号 `N` → `scene_{N-1}`（`scene_1.mp4` 回填到 `scene_0/video.mp4`）；无序号按上传顺序；可用 `scene_map`（JSON，如 `{"1":"scene_0"}`）显式指定 |
| 归一化 | 视频：等比缩放 + 居中 pad 到任务分辨率、30fps、H.264/yuv420p，有音轨则转 AAC（无音轨不补静音）；图片：PIL 等比缩放 + 居中 pad → PNG |
| 探针回显 | 回填结果附 `duration/width/height/fps/has_audio/vcodec/acodec`；缺音轨会标黄提醒 |
| 单文件探针 | `GET /api/tasks/{id}/artifacts/probe?relpath=scene_0/video.mp4` |
| 限制 | 仅在任务**暂停或未运行**时可导入（运行中 409）；`kind` 非 `image`/`video` → 422 |

> 工具列表由 `GET /api/providers` 下发（首期仅 `jimeng`，结构可扩展，但**不开放用户自定义工具**）。
> 每条注册项还带 `experimental`（是否试验阶段 → 前端「🧪 试验中」气泡）与
> `guide_path` / `faq_path`（官网说明与常见问题**路径**，前端按当前界面语言拼前缀）。

## 六、问题上报

修改后仍不达预期时，用检查点等待页的「📤 反馈问题」入口生成上报模板，包含：
任务 ID / 任务目录 / 检查点 / 使用的处理方式 / 修改前后差异 / checkpoint.json / 错误日志，
补充"期望结果 / 实际结果 / 复现步骤"后提 Issue。
