> **归档日期**：2026-09-20
> **调研范围**：与本项目同属"免费云端模型 + 自部署 Web 端"形态的创作平台，其常见功能模块的设计形态
> **组织方式**：按**功能形态**而非实现来源组织——每一项都独立描述"这个能力是什么、通常怎么实现、代价在哪"，不依赖任何原始出处即可理解与推进
> **当前状态**：✅ **已调研完成（2026-09-22）**——调研充分、处置明确：
> - 转入实施：P0-1 风格预设库 + P1 产物画廊（见 `../v6.0/gallery_and_presets_design.md`；预设库优化用户填入体验；画廊仅做展示、不做删除）；
> - 明确不做：P2 凭据站点分组展示（现存储/接口/UI 已具备，纯展示层边际价值）、对话式生成、自由画布、平台治理类能力。

## 一、调研方法

1. **横向扫描**：对照同类创作平台的功能划分，梳理出与本项目可能产生交集的模块（见 §2）。
2. **设计还原**：对每个模块，抽象出"数据形态 + 交互形态 + 服务端职责"三要素，写成可独立评估的设计要点。
3. **差距对照**：回到本项目代码逐项确认现状（§3），只保留存在真实增量的项。
4. **取舍**：按"与项目定位是否冲突"先做减法（§4 末），再按价值/代价排序。

> 本文档不引用具体实现的代码路径，也不复制任何外部代码；实施时由本项目按现有架构独立实现。
> §3 的现状结论均以本项目代码为证据（附行号），可逐条复核。

## 二、同类平台的通用功能形态

以下六类模块在同类平台中出现频率最高，逐一给出设计要点：

### 2.1 参数与风格预设库

- **数据形态**：预设为结构化记录 `{id, name, category, description, payload}`，其中 `payload` 是真正注入生成请求的部分（风格描述 / 运镜 / 提示词模板）。
- **来源分层**：系统预设随启动写入（只读，随版本更新），用户预设可增删改（需持久化到工作目录）。
- **交互形态**：生成表单的相应字段旁提供"选择预设"，并提供"把当前值存为预设"；预设带分类便于浏览。
- **服务端职责**：提供列表/详情接口；应用预设时只是把 `payload` 填入请求参数，不引入新的生成链路。

### 2.2 多凭据 / 多站点配置管理

- **数据形态**：凭据条目 `{credential, domain}` 或供应商记录 `{name, base_url, credential, enabled}`；凭据与站点的绑定关系必须显式存储。
- **交互形态**：设置页增删改与站点/域名绑定；生成请求按当前凭据（或当前站点）构造。
- **服务端职责**：请求构造时按凭据解析 base URL；故障转移与配额分摊策略需明确定义（同站点多凭据轮询 vs 跨站点故障转移是两件事）。
- **关键设计约束**：一旦引入"用户可改 base URL / 绑定域名"，就必须同时定义**凭据与站点的绑定粒度**，否则会出现凭据打到错误站点的隐性故障。

### 2.3 产物画廊（生成历史）

- **数据形态**：每次生成一条记录（类型、参数摘要、产物路径、缩略图、状态、耗时）。
- **交互形态**：网格/列表浏览、按类型与状态筛选、批量删除或下载。
- **服务端职责**：缩略图由服务端从成片抽帧生成（不要对整片重编码）；删除需与产物注册表联动做级联清理。
- **注意**：该模块是**展示层增强**，不改变生成能力本身。

### 2.4 对话式生成（工具调用驱动）

- **数据形态**：Chat 会话与消息记录单独存储；工具定义（生图 / 生视频 / 查询任务）以结构化 schema 声明。
- **交互形态**：用户自然语言描述需求，模型返回工具调用时服务端据此创建生成任务，并把任务进度流式回传（SSE 或轮询）。
- **服务端职责**：意图 → 工具调用 → 任务创建的映射，以及对"参数缺失时追问"的处理。
- **与本项目的关系**：本项目六种任务均为表单式创建，该形态属于**并行的创建入口**，不替代现有流程。

### 2.5 自由画布（节点式创作）

- **数据形态**：节点（图片/视频/文本）+ 边（引用关系）的图模型。
- **交互形态**：节点可拖动、连线、分组；节点上下文可作为新的生成输入（上下文感知重生成）；可由 Agent 以工具调用方式批量操作节点。
- **与本项目的关系**：定位差异较大——本项目是"输入文本 → 自动多场景编排"的流水线，画布是"人工编排 + 局部重生成"。**不建议引入**。

### 2.6 平台治理类能力（用户体系 / 额度 / 审核 / 社区）

- 用户-角色-权限、调用额度扣减、敏感词过滤、作品广场、后台审批等。
- 这些能力的前提是"多租户平台"，其复杂度主要来自权限与计费模型，而非生成能力。

## 三、现状盘点：与本项目逐项对照

| 能力 | 同类常见形态 | 本项目现状（已核对代码） | 真实增量 |
|---|---|---|---|
| 风格 / 提示词预设库 | 结构化预设 + 分类 + 一键应用 | **缺失**。`style` 是自由文本输入，无任何可复用模板（`frontend/src/components/forms/` 下各表单）；且 `CreativeForm.vue:24`、`PoetryForm.vue:25` 的默认值是**硬编码中文** `'电影质感写实风格'`——非中文用户打开表单即被预填中文风格描述，并被送入视频模型 prompt | **高**。从"全靠用户手写"到"可选模板 + 自定义"，且顺带修掉硬编码中文默认值的国际化缺陷 |
| 多凭据 / 多站点配置 | 凭据-站点绑定 + UI 增删切换 | **已具备**。`config.json` 的 `api_keys` 支持 `{key, domain}` 结构（`core/config.py:333-430`，含原子写 + `0o600`）；接口层有增删/追加/域名绑定/域名探测（`web/routes/config_routes.py:148-283`）；前端有对应管理界面（`frontend/src/components/ConfigPanel.vue`、`composables/useConfig.ts`、`api/index.ts` 的 `/api/config/keys*`） | **低**。仅剩展示层优化（按站点分组聚合呈现）与跨站点故障转移策略（当前语义为"按凭据轮询 + 各自绑定域名"） |
| 产物画廊 | 缩略图 + 筛选 + 批量操作 | 任务列表（文本 + 状态）+ 文件系统产物；已有片段预览能力（`core/artifacts.py` 产物注册表 + 级联删除），但**无缩略图画廊/批量管理** | 中。体验向，非功能空白 |
| 对话式生成 | 工具调用 + 流式回传 | 无（六种任务均为表单式创建）；`AgnesChatAPI` 已具备调用能力 | 中低。与结构化表单定位不冲突但也不急迫 |
| 无限画布 | 节点图 + 上下文重生成 | 无，且与流水线（多场景自动编排）定位不同 | 低。不建议 |
| 用户体系 / 额度 / 审核 / 社区 | 多租户平台能力 | 无。**刻意不做**（单用户自部署、永久免费、无登录） | 负向。引入即破坏定位 |
| 水印 | 平台级水印开关 | 已有水印能力（moviepy TextClip + ffmpeg overlay），且对外宣传"无水印" | 无 |

> 本节结论基于 2026-09-20 的代码核对。其中"多凭据配置"一项在初次评估时被误判为缺失（只看了单凭据接口），复核后已修正——这正是本文档要求"逐条附证据"的原因。

## 四、拟增强内容

按价值/代价排序：

### P0-1 风格与提示词预设库

**数据形态（建议）**

系统预设：只读目录（如 `resource/presets/styles.json`），**只存 id 与提示词本体**，名称/描述走前端 i18n 翻译表（避免在 JSON 里内联 22 种语言）：

```json
[
  { "id": "cinematic_realism", "category": "realistic",
    "prompt": "cinematic lighting, shallow depth of field, 35mm film grain" },
  { "id": "ink_wash", "category": "oriental",
    "prompt": "traditional Chinese ink wash painting, rice paper texture" }
]
```

用户自定义预设：持久化到 `.agnes_config/presets.json`，名称由用户自填、不参与翻译：

```json
[
  { "id": "u_1", "name": "我的冷色调", "category": "custom",
    "prompt": "cool desaturated color grading", "created_at": "2026-09-20T10:00:00" }
]
```

**交互形态**：`style` 输入框旁提供"选择预设"下拉（按 category 分组）+ "保存当前值为预设"；自定义预设可删除。

**顺带修复**：`CreativeForm.vue:24`、`PoetryForm.vue:25` 的硬编码中文默认值改为空值或按 UI 语言取默认（建议改为空，让"不填风格"成为一个合法选择，与后端 `style: str = Form("")` 的默认一致）。

**代价**

- 后端小：静态目录 + 用户预设的读写接口（沿用 `.agnes_config/` 既有持久化，无需引入数据库）。
- 前端中：选择器 + 保存/删除 + 空值默认的联动。
- i18n 中：每新增一条系统预设需补 22 语言 × 1 个名称 key（`scripts/i18n_check.py` 缺失即拦截回归）。**建议首批控制在 10-15 条**，只做有明确拍摄语义的风格（写实/水墨/动漫/胶片等）。

**验收**：creative / manuscript / poetry 三处均可选预设；预设为空或用户不选时行为与现状完全一致；非中文界面下 `style` 不再预填中文。

### P1 产物画廊（缩略图 / 筛选 / 批量删除）

- **设计要点**：与现有 `core/artifacts.py`（产物注册表 + 级联删除）天然契合，作为任务列表的展示层增强；缩略图用 ffmpeg 抽单帧生成，**不重编码成片**。
- **代价**：后端小~中（抽帧 + 索引字段）；前端中。

### P2 多凭据的站点分组展示（低优先）

- **现状**：存储与接口已支持 `{key, domain}` 绑定（见 §3），前端是平铺列表。
- **增量**：仅展示层——按 `domain` 聚合成"站点分组"，并在切换策略上给出显式说明（当前为按凭据轮询）。
- **代价**：前端小（1-2 人日）；若同时要引入"跨站点故障转移"新语义，则涉及限速桶与错误收集的回归，成本上升到中。

### 明确不采纳

用户体系、额度/积分、RBAC 权限、敏感词审核、作品社区、无限画布、Agent 工具市场、3D 场景编辑——与"单用户、自部署、永久免费、无登录"的项目定位直接冲突，采纳即改变产品性质。

## 六、未实施原因

1. **不在当前路线图**：`optimization_roadmap.md` 批次 0-3 已全部标记完成，剩余精力优先给稳定性加固（见 `../v6.0/stability_hardening_PRD.md`）；
2. **P0-1 的 i18n 成本有被低估的风险**：22 语言同步是硬前置（`i18n_check.py` 缺失即中断回归），需先把首批预设内容与翻译流程定下来；
3. **P1 需要先定缩略图的生成时机**（创建任务时 / 合成完成后 / 首次访问时），否则会与合成阶段的性能优化相互干扰；
4. **同类平台的功能形态仍在快速演进**，其数据结构尚未稳定，现在照搬形态有返工风险。

---

## 七、复查触发条件

满足任一条件时可重新评估并决定是否转入 `optimization_roadmap.md`：

1. 用户反馈中出现**集中性的"不会写风格提示词 / 想要模板"**诉求（issue 或社区）；
2. 出现非中文用户因默认风格预填导致生成结果不符预期的反馈（对应 §4 P0-1 的顺带修复）；
3. 稳定性批次（`stability_hardening_PRD.md` Phase 1-3）全部落地且前端有余量；
4. 同类平台在该模块上出现趋同的稳定设计（多方实现一致），说明形态已收敛、可安全借鉴。
